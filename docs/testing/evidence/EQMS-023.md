## Functional observations

- Two independent documents retain stable IDs and exact saved revisions across
  reopened `Documents` instances and CLI process launches.
- Canonical round trips quote titles safely, normalize CR/CRLF to LF, and reject
  invalid title/ID/schema input. Saved history/diffs select exact revisions and
  reject expressions and another document's revision.
- Create/save preserve baseline HEAD, journal bytes, the Git index bytes,
  unrelated staged content and untracked files. Baseline verification still passes.
- Stale saves fail without advancing history; two concurrent saves from one
  token produce one success and one failure. Unchanged content retains its revision.
- Holding the draft ref's Git lock prevents publication after objects/commit
  construction. Show still returns the prior revision; removing the lock allows
  save/reopen of a complete revision. No pending baseline journal is created.
- Tampered ref/content/journal/file mode, missing identity, and authoring from a
  manually checked-out internal draft fail explicitly.
- UI tests cover new unsaved creation, busy-save duplicate prevention,
  failed-save edit retention, history/comparison, dirty project navigation,
  dirty close cancellation and document discard.
- Desktop tests reject malformed/wrong-schema/wrong-command/wrong-document
  responses, non-Draft metadata and process errors. Real Git process tests
  verify exact large UTF-8 stdin bytes and early nonzero failure without a
  broken-pipe false success or blocked pipe.

## Failures, warnings and limitations

- An initial formatting attempt exposed a duplicated visibility modifier while
  exposing an existing workspace helper; corrected before tests. An intermediate
  whitespace check caught a Markdown hard-break space; corrected. Final
  formatting, lint, whitespace and automated suites pass.
- JVM/Skiko emitted a native-access warning on this JDK. It did not fail the
  suites. No unrelated JVM configuration change was made.
- No forced power-loss/process-kill experiment or filesystem fault injection at
  every Git object write was performed. The tested failure boundary is final
  ref publication; transaction design leaves all earlier writes unreachable.
  Atomic ref durability relies on Git/filesystem guarantees, not a new proof.
- Windows/Linux runtime/path behavior and browser runtime were not executed.
  Existing platform safety limitations remain documented in EQMS-005.
- No manual desktop acceptance run, human review, signing, approval, publication,
  reference validation, remote backup/sync, performance benchmark or distributed
  consensus testing is claimed.
- Draft author/time are configured/local claims. Local history replacement is
  outside the trust guarantee. After a lost creation response, inspect list
  before retrying; exactly-once creation across client-response loss is not provided.
