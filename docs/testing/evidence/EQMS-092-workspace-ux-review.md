## Review scope and traceability

R092-21 / T092-18 addresses the four review requests:

- Tool panels and central editor have clipped 10dp rounded surfaces, with
  8dp quiet gutters and separation from the surrounding shell.
- Hover hints open inward beside their icon, vertically centered on the icon
  bounds, independent of the pointer's vertical location.
- Both horizontal split boundaries drag with an east/west resize cursor.
  Moving either boundary resizes the central editor and that side's active
  tool panel. Project/Search and Review/History share these bounded widths.
  Disabled/busy splitters do not move; keyboard minus/plus controls remain.
- IntelliJ-style editor tabs use Jewel Markdown/close icons and theme tokens,
  quiet inactive labels and a rounded selected surface. Close is integrated,
  descriptive and independently focusable. Dirty markers and historical
  qualifiers are separate from ellipsized titles. Active overflow tabs scroll
  into view after measurement without reconstructing editor buffers.

The small shared tab primitive preserves the existing accessibility names,
focus and disabled semantics that the pinned Jewel TabStrip cannot currently
provide directly. The design documents this deviation; no dependency was added.
Existing dirty-close, lifecycle, modal, shortcut and caret safeguards remain.

## Corrections and limitations

Initial development compilation required implementing PopupPositionProvider
as an object rather than a SAM lambda. Test-authoring failures from misplaced
test declarations were corrected before the final run. The geometry assertion
initially measured the full popup overlay root, not the hint content; it now
checks the actual rendered text bounds.

The overflow test exposed an actual tab-reveal timing bug: requesting visibility
before the tab was measured did not reveal a newly opened tab. Tabs now have
stable composition keys and request visibility after measurement and selection.
The regression passed in the final complete run. Failed development attempts
are not counted as passes.

The prepared 10k reference search benchmark remains unconfigured/skipped.
No new p95 claim is made; rail/tab changes do not change search query/results
rendering. Native release/adapters were exercised, but the unchanged full Rust
unit/Clippy suite was not rerun. No packaging or Windows/Linux native runtime
execution was performed.

The successful JVM run still emitted Skiko native-access and Cocoa AWT
window-deallocation/AppKit-thread warnings. These runtime warnings and
physical OS/assistive-technology behavior remain manual review limitations.
Effective retains its existing internal-only meaning, not external publication
or authenticated approval.
